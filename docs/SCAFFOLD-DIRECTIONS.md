# 临时脚手架建议：实现口径（scaffold-directions-1）

一句话：**优化 AI 多想一层“什么临时能力能帮工作模型做得更准”，然后把这件事写成方向性建议**；具体搭什么、怎么搭、怎么验，全由工作模型决定。

## 注入文结构

```text
【制作建议】       ← 决定成品水平的方向
【临时脚手架建议】 ← 值得临时开发/复用的制作与自反馈能力
【Ask用户(ask_user_question)】 ← 只需问题，选项由工作模型组织
```

三段合计上限 **3000 token**（是天花板，不是配额）。开头一句让建议“值得优先考虑”，同时明说**不覆盖用户明确要求、不自动成为逐条硬性要求**。

## 边界（这些是本轮收回的东西）

| 不做 | 原因 |
|---|---|
| 关键词/正则兜底补 `inspect` | 那是宿主替模型填答案，不是优化 AI 的判断 |
| 工具注册、任务级耐久索引、结果信封 | 那是另一项功能，不是“脚手架建议” |
| `firstUse` / `stopWhen` / 回报协议 | 会把方向性许愿变成执行流程 |
| 自动删掉含形态词的句子 | 粗暴；保留“不许自相矛盾”的提示词纪律即够 |
| 给 Ask 预置选项和“未定时默认” | 选项由工作模型思考；默认答案会变成替用户拍板 |

## 模型输出与渲染

- 输出 JSON 增加 `scaffold` 字符串数组（`add` 是制作建议，`ask` 是问题）；
- `scaffold` 坏值只丢该字段并记警告，不连坐整轮；
- 渲染只做净化与编号，不再有“本轮先做的动作”“执行要求”这类祈使段；
- 旧包里的 `decide`（问题｜选项｜未定时假设）只取竖线前的问题。

## 真实输出核对

用用户当次跑车需求的逐字原话、deepseek-flash、max 思考、**关闭只读工具**，跑一次真实优化：

- 输出：制作建议 7 条、脚手架建议 3 条、Ask 3 条；三段合计 970 字符、1521 output tokens（累计 2330，未触上限）。
- 脚手架三条都是方向级：可复用的本地检查回路（改完自动加载/截图/收集错误与帧率）、把形状/材质/场景/驾驶/相机分层成可反复调用的模块、准备可反复对照的审美参照方向。**没有出现代码、命令、参数或工具协议**。
- Ask 三条追问 CDN 依赖、驾驶手感取向、目标平台——都属于确实需要用户拍板的取舍。

复现：`po06/scripts/check-scaffold-directions.mjs`（需要本机已安装的适配器与凭据；不打印任何密钥）。
