# 通用解题增量选择：实施与 Flash 对照

当前本地候选：**contribution-selection-4**，已在最新自然任务运行。新计划见 [执行计划](PLAN-CONTRIBUTION-SELECTION.md)，结构化原始产物与限制见 [验证证据](evidence/CONTRIBUTION-SELECTION-FLASH.json)；最新自然任务失败与候选4证据见 [最新失败修复证据](evidence/LATEST-SELECTION-FIX.json)。本轮不回滚稳定的语言、权限、取消、版本或issue修复，不加入任何坦克、算法或写作领域模板。

## 实施

优化器按贡献对关键判断、困难构造或实际成品的作用选材；保留必要长推导和可采用片段，开放选择交由执行者整合。数值/配方说明事实与适用条件，新增依赖与工作量作为代价；重度提高探索与筛选深度，不以项目子系统覆盖或条数/字数代表力度。

常驻顾问指引只保留贡献、重要验收、授权和失败状态原则，参数、阶段、范围与材料细节由已有工具说明/实际状态提供。中文1264→270字符，英文2474→907字符。工具API、完整契约和机械校验保持。正常产品没有新增模型调用。

第一稿精简时漏掉了原来明确的反例检查，独立Flash改进指出这一损失，随后用短句恢复“检查关键不变量与反例”。没有把试题的分隔符、图算法或参数写进提示。此前候选重度系统为中文796、英文2283字符；自然任务失败后新增了执行停止判据与机器意图降权，当前候选重度系统记录为中文985字符；缩短不是质量判据，也不限制真正必要的长输出。

三档/双语、实际注入、旧默认迁移与自定义保留通过定向回归。旧默认使用冻结的真实文本夹具，不从新提示动态造“旧版本”。相关27份离线文件合计 **250通过、0失败、0跳过**（包含机器意图尾置回归）。

这点还说明：给更有价值的构造并不等于每个片段都正确。实际证据和工作模型判断仍然必要。不能把“提醒反例”就写成反例已经被识别。

## 失败与对照有效性

首批low档有旧优化器把原任务里“最终JSON格式”误当自己的输出格式，以及新算法思考耗尽8192输出token上限，不能评分成新臂优势。保留全部记录；只对算法/数据两题补一次共同明确source边界、两组均off的对照，任务和评价标准不变。写作已有效，不重采。

首批9次生成40412token、对称补查8次16345token、最终单题2次4974token，产物/辅助生成共19次61731token。另有初始顾问方式咨询（引用校验失败，报告54283token）、一次限定Flash改进4192token、两次源码复核6259/11456token。本轮所有已报告用量合计 **137921token**，全部Flash，不隐去设置失败和补证成本。

源码复核确认通用选择、三档、精简指引及迁移/自定义保留的可见接线，仍把部分API运行证明标unverified，reviewPassed=false；没有正式放行，也没有为形式性通过继续重复咨询。初始顾问原始草稿还引用了过时的历史档位描述，未当事实或通过依据。

## 最新自然任务失败后的候选4

最新坦克会话证明候选2仍会把开放目标扩成完整施工清单。真实浏览器最终能正常加载并进入就绪，不能把早期虚拟时间截图的 CDN 提示当主因；但真实图像和执行链仍暴露了模型方案过度铺开的实际结果。顾问工具在会话中可见但没有被调用，执行者改用替代自测与大量局部修改，最终没有真实 WebGL 证据。

候选3先加入执行者能力边界并把机器 intent 移到贡献末尾；同一 Flash 原文包约4052字，仍有11条清单式建议。独立失败诊断后，候选4只增加重度停止判据：从最高杠杆的未解决判断开始，覆盖核心瓶颈即停，不遍历所有子系统，只有会改变判断的细节继续展开。相同原话、DeepSeek Flash、max、单次结果为：

- packet 约 **4052→2603 字**，raw 约 **4109→2649 字**；
- add **11→10**，数值片段 **70→18**，祈使式约束 **7→6**；
- 履带、弧长、差速、悬挂、炮塔、光照和性能等困难内容仍存在；
- output tokens **12331→13222**，总 tokens **12900→13825**，耗时 **85.0→81.2 秒**，所以不能宣称降本；
- 这仍是一题同题 follow-up，不是新的独立 A/B，也没有执行最终成品。

这支持“通用施工清单有所收敛”，不支持“模型普遍变强”。若新自然任务仍然大规模列清单，下一步不应继续堆提示词，而要把是否接受宿主侧选择/丢弃规则作为明确取舍交给用户；那会有丢掉困难长推导的风险。

## 最新自然会话：顾问截断与真实交付回归

最新实际会话 `session-33973b46-66ff-49c4-acc7-0ee2c1d9a652` 使用 contribution-selection-4、DeepSeek Flash、Max。优化注入约4659字，执行阶段进行了26次根工具调用；其中顾问只调用了一次 `improve_result`，运行约300秒后返回 `advisor-timeout` partial，没有完整报告。执行者随后把 partial reasoning 当成可采纳的独立观感复核，继续修改了6处光照/阴影/后处理参数。

实际进度记录显示顾问进行了14次查证，累计112943字符思考，最终报告正文为0。没有图像材料，不能据此确认六处参数改动提高了真实画面。四次JavaScript web_fetch失败后执行者已改用bash/curl查源码；这些初始错误是额外成本，不等于所有API未核对。

最后自验读取了最新HTML，却裁掉main启动，并明确不调用刚改过的initEnv，只手工复算阴影公式和仿真车辆。因此“全部修复已验证”没有覆盖变更路径。真实Edge复现ENV.skyDir缺失导致启动失败；本轮初始化了该字段，并修正预设sunCol被错读为sunColor的问题。初始化后暂停动画，使用原渲染管线得到 [实际WebGL图](../.po06-tmp/latest-v4-real-webgl-4.png)。形体仍有明显拼块感、结构粗糙和颗粒遮挡，未达到精细写真；静态图不证明GPU性能或完整交互。

本轮按你的意见取消了顾问插件的**默认总时间上限和强制最小/最大钳制**：

- 默认 `timeoutMs` 现在为 `null`；只有显式设置 `DSH_PO06_ADVISOR_TIMEOUT_MS` 才启用调用方截止。
- 只读工具循环接受 `budgetMs:null`，仍保留最多只读轮次、外部取消、provider流结束和输出终止。
- 没有截止时UI不再画假定五分钟的进度条，仍显示已运行秒数。
- 显式超时的 partial 保留与取消路径仍通过测试。

最终回归日志含30份相关文件，Node报告 **269通过、0失败、0跳过**，见 `.po06-tmp/latest-session-final-regression.log`。新增虚拟时间测试推进到15分钟，默认顾问不被中止，用户取消仍等待模型收尾，读工具分支也能正常完成完整报告。见 [最新审计与修复证据](evidence/LATEST-SESSION-DISASTER-FIX.json)。

这修复了“顾问被五分钟硬切导致建议不完整”的确定机制问题，但不代表最新成品已经达到写真质量，也不证明顾问结果本身正确。
