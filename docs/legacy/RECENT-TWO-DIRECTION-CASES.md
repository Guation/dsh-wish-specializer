# 最近两个方向增强案例：成品残缺从哪里来

结论：新英文 max 案例确实留下了可复现的成品错误，并且存在“已见到失败，却用不等价的证据把它降成仪器问题”的推理错误。与此同时，“3+3 跟随 max”的方向阶段因 1024-token 小预算发生大量无效调用，不能当作实际进行了三轮有效纠错。两个案例共有方向正文越界为伪工具调用的问题。不能据此证明英文或 max 本身比中文/fast 差。

## 三个可独立复现的小错误

1. **履带路径确实回折，不能判为仅仪器问题。** 最终 `buildTrackPath()` 传给 `buildRun()` 的圆心 z 次序为 `[-3.30, 2.05, 1.33, 0.61, -0.11, -0.83, -1.55, -2.27, 3.28]`。算法要求按行进顺序输入，但车轮次序在中间反向，路径因此往返。137 节、名义 pitch=0.178600834m，首尾闭合=0，这些标量都成立；然而相邻点在未做地面压平前也可只有 **0.0015413m**，平地压平条件下可低至 **0.0000289m**。原日志最小 0.0003m 与本轮平地/不同 phase 扫描的 0.0000289m **不是数值完全吻合的同一次测量**；它们共同支持路径空间近重合这个现象。等弧长只是参数空间的构造，不保证输出空间不重叠。
2. **炮塔局部/世界坐标消去错误。** `updateTurret()` 同时从 localYaw 和 desiredWorld 两边减 hullYaw，差值里 hullYaw 抵消；真正赋给 group 的却仍是 localYaw。用最终原函数，车体转 90°、世界目标保持 0°，运行 120 步后炮塔仍局部 0°、世界 90°，没有保持原目标。
3. **FPS/帧时统计每帧拿到 undefined。** 最终 frame 先执行 `HUD.fpsTick(dt)`，再赋 `var dt = ...getDelta()`。var 为当前调用局部，下一帧仍先见 undefined；HUD.acc 变 NaN，不再更新。日志 seq1134 已显示 0 fps /1000ms，却只确认“文字画出来了”，没有检查数字是否正确。

最小复现从最终 HTML 直接截取原函数，仅补 TAU/clamp 与最少状态；不改代码，不重新实现函数。扫描 1800 个 phase×137 对链节；另独立跑炮塔与 FPS 函数。执行脚本 [.po06-tmp/recent-direction-cases/reproduce.mjs](../.po06-tmp/recent-direction-cases/reproduce.mjs)，原始输出 [minimal-reproductions.json](../.po06-tmp/recent-direction-cases/minimal-reproductions.json)。前后成品哈希一致。不是完整 GPU/真实交互重跑，不能代表作品所有缺陷。

## 错误为何被保留下来

- 履带 world-spacing 在 seq1179 报 FAIL；seq1189 修了地面过渡仍 FAIL；seq1210 只证明 dArc=pitch、closure=0，却推成“path exonerated”。探针确实把最小 pair 的坐标用最终状态重算，这是一个真实仪器缺陷；但它不使累计最小距离的失败失效。
- seq1197 的 `TEST[all] ALL PASS` 实际是 10 个 drive/fire 标量断言；没有覆盖 world-spacing、转向后的炮塔世界朝向、fpsTick 时序。测试不是没运行，是断言与完成口径不等价。
- seq1231 试图修探针的 Python 语法错误，包仍为 1457333B，最终又将剩余问题表述为“只影响开发仪器，不影响成品”。这属于已知失败降级，不能靠“已披露限制”把实际缺陷变成完整。
- 方向模型读了与工作模型相同的上下文，会重复当前假说。后段多份方向也沿用“path exonerated/instrument only”的解释；方向并非独立反证，更不是实际重新执行的验收。

## 共同缺陷：方向候选并不总是方向

只数最终真的交接给工作模型的正文：最新 130 条里 **44 条**带 DSML 等伪工具协议（涉及 15 步），旧 141 条里 **41 条**带类似协议（涉及 21 步）。可见模型有时直接续写 run_code/代码或完整答复，偏离了“短方向”。这些文本不会由宿主当工具执行，但会作为方法建议送入工作上下文。

现有边界只检查 tools 数组、finish、长度和 Markdown 代码围栏；literal DSML 属于普通 text，能通过。它解释的是角色分离不可靠，不单凭 marker 就证明所有后续 bug 都由它导致。

## 为什么旧案例更容易闭合

旧作品选了较直接的解析闭环履带，验证了接地点对地滑移、原地转向、矩阵里的俯仰/炮口位移等结果；修正了炮座偏移叠加、后坐冲量符号、重复后处理 mesh、雨夜变黑等问题。使用了更贴近实际输出的差分对照，而不只是构造量。

新作品投入了离线内联、自写 AO/DOF 链、相机、悬挂、调试工具等较多相互作用面；并非只是“多写了功能”，关键是路径方向、局部/世界变换、每帧初始化顺序这些接口约束没有同时稳定。多轮方向复制原假说可以使解释越来越确信，不能保证实现越来越对。

旧作品也有 CDN 首次联网/软件渲染等限制，未证明完全无 bug；截图美观与完整性是不同维度。两例不是控制实验，不能归咎于英文，不能断言 off 普遍胜过 max。

## 通用改进顺序（本轮不实施）

1. 先保证增强真的在工作：为方向角色设匹配的预算/思考策略，与原工作模型强度分开；输出为空或被截断时清楚显示有效方向数，而不是仅显示请求 3+3。保留用户显式设置，不偷偷改主模型档位。
2. 守住思路与执行的边界：不把伪工具协议、完整实现或最终交付文本交回为方向；不传私有 reasoning。继续让原模型取舍，绝不恢复独立裁判。
3. 将实际矛盾驱动的定向反证与普通发散构思分开：观察到 FAIL 后，方向应提出不同解释和能区分解释的最小观测；不继续多数复述同一“已排除”假说。是否采用仍由原工作模型判断。
4. 维护未闭合证据与对象版本：一个失败必须被同对象结果复测消除，或有直接反证证明仪器误报；代码没改、测量仍失败、修补命令报错时，不能换一句叙述就标“已排除”。是带依据的问题状态，不是建议采纳配额。
5. 完成判断盯住输入→变换→可观察结果的接口：顺序/符号/坐标系/更新时机/单位，优先用独立期望与差分检查；“语法过、图不是黑、几条自测绿”都不能替代完整主路径。保持成品目标，不以删掉用户想要的精细度换表面零错。

方向提升构思宽度，纠错依赖新事实和证据闭合。当前故障同时涉及模型推理、增强角色实现和交付判断，继续增加 max 方向或循环次数会增加成本，未必增加有效反证。
