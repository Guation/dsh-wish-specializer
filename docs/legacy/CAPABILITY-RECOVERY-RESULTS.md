# 能力恢复：实现、实际体验与验证

> 已被用户指定的第300～305轮精确回归取代。此处是上轮部分恢复及单题证据，不是“回到两个突破点完整实现”的证明。当前状态与例外见 [精确回归记录](ROUND305-RESTORATION.md)。

本地修订：**capability-recovery-1**；咨询条件：**contribution-opportunities-1**。实施计划见 [PLAN-CAPABILITY-RECOVERY.md](PLAN-CAPABILITY-RECOVERY.md)，完整结构化证据见 [CAPABILITY-RECOVERY.json](evidence/CAPABILITY-RECOVERY.json)。

本轮恢复的是两个突破点的行为角色，不是整树回滚。历史来源见 [成功编辑还原与因果分析](POST-BREAKTHROUGH-ANALYSIS.md)。

## 已实施

- 默认双语核心与light/standard/heavy来自实际route-a-1成功历史编辑，内容与独立历史夹具逐字一致。恢复关键规律、困难构造和可采用内容，不再要求拼出完整工程路径或覆盖瓶颈即停。
- 顾问COMMON/APPROACH恢复早期独立具体贡献目标；当前图文、新旧版本、材料角色、头尾选择、引用、版本保护仍保留。没有拆回旧解析/材料代码。
- 咨询由预期收益决定，不按每个重要选择或初稿打卡；不要求先证明自己有缺陷，已经满意也不排除改善。重要成果仍独立核验，keep与建议不等于验收。
- 空补充且无当前状态/反馈时，执行上下文不再附整段顾问流程。真实身份错误、非空失败反馈仍可见。
- 阶段默认反馈只给状态计数、对象、动作和可调用的status参数；已确认failed检查仍带原ID和简短内容。完整status/reviewSpec与advance机械判据不变，不自动关闭旧问题。
- 中断返回及回放标记diagnosticOnly/adviceReady:false，诊断记录保留。它不是完成的建议或验收；采取其中线索仍需实际证据，没有自动续跑。
- 模式错误保留原reason并给correction；taskId/stageId明确仅review_result。未放宽类型、授权或阶段规则。
- 工具回退把前次与无工具回退的已报告usage合计，缺报调用标未知；外部取消后不再发起付费回退。
- 机器解释失败通知不再推断“用户没有新要求”或要求用户重说；用既有机器建议类型保留非阻塞通知，不进入用户未决项。合法零增量依然一步成功。
- 当前/历史内置默认可精确迁移，真正自定义保留。原生英文、字面保真、原话、会话、权限、版本、取消、顾问默认无总时限与旧issue修复保留。

没有领域模板、硬条数/字数、新模型调用常规路径、强模型、多候选循环、发布或个人设置修改。

## 接线验证

36份相关套件，Node报告 **299通过、0失败、0跳过**。包含原话/解析/编译/真实context入口、材料角色和版本、默认迁移与自定义、长顾问与取消、阶段/未验证保护、UI卡片、全部已修issues等。日志： [recovery-final-regression.log](../.po06-tmp/recovery-final-regression.log)。

新增测试以实际入口验证：两次报告usage均入账、未知不是零、取消不启动回退、无效模式不调用runtime且给纠正路径、partial进度回放同样是诊断、压缩状态不丢confirmed失败及full contract、空context可退场、机器失败不创造用户歧义。没有按test数断言模型更强。

独立Flash代码复核列出六项局部代码检查satisfied，未发现具体重要回归；整体仍gaps/reviewPassed=false，因为没有证明普遍模型收益或完整运行验收。本报告保留该界限，不再为pass重复咨询。

一次方案贡献因模式输出不合格未接受，一次改进草稿引用了不存在的R0.workflow等编号，假设不存在的policy.hasStageState，并误判空反馈分支；未采纳。已有测试证明非空真实失败反馈不会丢失，原始失败记录保留，不把顾问的自信当新需求。

## 新的开放任务

在看输出前固定“下潜：从海面到深渊”单HTML交互科普展页：可控制下潜/暂停/回海面/拖深度，场景的潜水器、生物、地貌随深度变化，有可靠且可探索的知识标注，桌面/手机/键盘可用，完全离线。任务没有写入产品协议。

三组同Flash/max、同原请求：无辅助、冻结候选4（current）、恢复版。实验使用一次无工具的完整HTML生成，不能等同完整日常agent协作。

首批实验人为24000输出token上限让三组执行回复全耗尽、最终正文0，无法评成品。这是设置失配。失败和费用保留，只有成品调用在生产SDK默认预算下各重做一次，未重生成两份辅助，没有改任务、评分或提示。无辅助组idle超时、文档未闭合、用量缺报，不能用这个缺失证明辅助强于原始提示。

current和恢复组都完成了一个HTML，但夹带前后说明。两组按相同规则提取唯一doctype到html闭合标签，不改内部字节；格式不遵守仍另记，恢复组暂停拖动缺口不手修。

真实浏览器对两份原始HTML禁用HTTP/HTTPS联网，启动均无Runtime异常、无外部请求，移动宽度均不横向溢出。下潜、暂停、滑动/滚轮和按正常动画回海面有真实状态记录，不用源码或声明冒充运行。

恢复组暂停后调整深度目标不更新实际深度，因为暂停把dt设0并冻结目标插值；这项缺口已复现/源码关联，仍保留。恢复组画面拖动方向与current相反，不能因此判不支持拖动。键盘触发器/焦点策略不同，没有完整键盘流程验收，不把一次无效合成事件当全面失败。

用户实际体验反馈：**“恢复组明显强于current组，虽然截图上可能觉得后者更好，但实际体验上，恢复组做的动效，以及知识科普和各个东西的联动都远超current组。”** 原话单独留档于 [用户体验记录](../.po06-tmp/recovery-user-experience.json)。这是这道题的体验证据，不是统计通用优势；静态图片排序不能替代动画/内容联动。

当前决定：恢复方向在这题有实用收益证据，保留capability-recovery-1为本地候选。不是因为恢复组更短——它的辅助3931字符比current的2586字符更长；也不因为所有程序用例全对，暂停手动探索仍有缺口。

全部实验/独立意见共11次模型请求，已报告287001token，包括被测试预算截断的100707token和三次独立意见。无辅助生产预算那次传输错误未上报usage，其费用未知，不记为零。没有重复生成直到恢复组胜出。

有效成品每组一份；不能剥离核心恢复与咨询语气各自因果，也不能证实恢复组稳定更好，不能证明强于更强模型。当前一次完整HTML生成没有工具/运行中的顾问，尚不能代表正常长项目与独立贡献采用链。
