# 历史文档（legacy）

> **这些文档描述的是过去版本的计划、验收与实验，不代表当前行为。**
> 如果你（或你的 AI）在判断“这个插件现在怎么工作”，请只看 [../INDEX.md](../INDEX.md) 里列出的现行文档；
> 本目录只作为历史证据保留，用来追溯“为什么当初那样设计”。

## 为什么要单独存放

这个插件从 0.5 走到 0.9，中间换过命名（`dsh-po06` → `dsh-arbiter-wf` → `dsh-wish-specializer`）、
换过注入协议（v1/v2 → 三段方向建议 v3）、也撤掉过整块能力（工具箱计划）。
旧文档里的大量结论**在当时成立、现在不成立**，混在一起会让新读者（尤其是 AI）得出错误认识。

## 目录约定

| 前缀 | 来源 | 含义 |
| --- | --- | --- |
| `docs/legacy/` | 原 `docs/` | 各版本的计划（PLAN-*）、验收（ACCEPTANCE）、实验与事后分析 |
| `po06-` 前缀 | 原 `po06/` | 0.5–0.6 时代的 UI 规格与帮助页 |

## 阅读纪律

1. 这里的数字、判据、文件名都可能过期；**不要引用它们当作“当前契约”**；
2. 如果一份历史文档与 `docs/INDEX.md` 里的现行文档冲突，**以现行文档为准**；
3. 需要判断某个旧结论是否仍成立时，用 `po06/scripts/` 里的脚本重新跑，而不是引用本文档里的结论。

## 注意：有些文件**不能**移进来

`po06/HELP-0.6.md` 与 `po06/HELP-0.6.en.md` 名字看着像旧版说明，但它们是**运行时资产**：
`/po06/api/help` 会直接读取它们作为界面帮助文本。以后清理文档时不要移动它们。
