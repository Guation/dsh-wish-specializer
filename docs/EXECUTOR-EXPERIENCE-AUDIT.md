# 从执行AI视角审视插件全流程

状态：只读审计完成；没有新增真实模型调用，没有修改提示词、权限或插件行为。结论来自我在本次协作中实际收到的上下文/调用结果、两份最近完整自然任务、当前源码，以及两个离线API探针。使用感受是对可见信息和动作负担的判断，不是假装能读取模型内部注意力，也不等于Flash与当前执行模型有同样的能力。

## 主结论

当前插件更成熟的部分是工具运行保障、原话/材料身份、取消与版本隔离。贡献选择与把独立意见转成最终产物的部分仍未达标。它有时补上具体难点，但经常让我同时完成原任务、筛选一份机器方案、解释额外验收状态。局部程序正确性、包更短、调用成功不能替代产物收益。

真正有用的标准：这次输入有没有让我改变一个重要判断、得到更好的构造/内容，或发现真实偏差，且收益值得新增代价？困难长推导可以必要；重复常识和同一配方的长期暴露通常不必要。

## 可核对的事实

### 1. 长补充不只是一次阅读

两个完整自然会话分别为：

- session-b4410b11-4f67-4206-91f5-f9e7919ba1f0：74字原话，8109字补充；5个用户侧上下文更新快照原样出现约8838字的运行上下文，包含整个辅助包。
- session-33973b46-66ff-49c4-acc7-0ee2c1d9a652：同原话，4659字补充；6个更新快照原样出现约5388字运行上下文，直到顾问返回后的最后阶段仍是同一包。

这些是记录中的上下文快照，不等于5/6倍新增可计费token；缓存、投影替换与历史装配会影响实际账单。但可以确定同一整套建议长期存在，当前实现也持续渲染当前packet，而不是随已解决对象自然淡出。入口见 [动态上下文](../po06/lib/index.js#L1787)、[状态渲染](../po06/lib/capability.js#L248)。

[withAdvisorWorkflow](../po06/lib/advisor-workflow.js#L5) 在辅助开启但没有补充时也注入270字中文协作规则；关闭时为0。这个常驻原则比旧版短，但仍不随普通讨论/简单确认退场。

### 2. 机械权威区分不足以消除行为锚定

最新意图把“不要预览其他文件”解释为“既不作参考也不引用”。第一批建议又给了完全程序化/自足实现政策。这些不是用户原话的同义复述。把意图移到末尾明确标记为非权威是好的局部修复，但同样的新增限制还会留在add正文中；标题说明并不能自动保证语义忠实。

数据结构中的provenance=machine避免冒充法律意义上的用户授权，这必须保留。但执行模型依然会受具体方案、命令语气和其上下文位置影响，不能把“声明是建议”当成原意守恒的证明。

### 3. 顾问有帮助，也有非常高的整合代价

我实际得到过值得采用的独立意见，例如恢复通用不变量/反例检查；也得到过引用错误、过时历史信息，以及需要多次补材料的unverified。独立分析不是同模型自动升级，同一基础模型仍可能带着同样的偏好与知识错误。

最新自然任务进度记录：14次查证、4个模型轮次、112943字符思考、完整报告正文0，300秒被截断。执行者依据保留的思考做6处修改。取消默认总截止已完成，但这不是让无边界思考自动变有用；真正决定收益的是原问题、材料和最后可采用内容。

这个调用问了材质/光照/曝光/bloom/机位的一整组参数，没有图像。它更容易在执行者已有方案里调参数，而不是发现决定原目标的粗糙主形体。源码能支持代码层事实与条件推断，不能确认实际像素好坏。详见 [自然任务证据](evidence/LATEST-SESSION-DISASTER-FIX.json)。

### 4. 成功通过某个流程不等于成果通过

最新实际交付初始化失败，因为后期编辑引入ENV.skyDir却没有初始化。最终测试读取了最新文件但裁掉main启动，明确不调用initEnv，只复算阴影公式和运动学。这不是“旧文件测试”，而是“当前文件中相关路径未测试”。随后发现sunCol/sunColor错配。

这两处已修，真实Edge能渲染，但 [实际图像](../.po06-tmp/latest-v4-real-webgl-4.png) 仍有明显拼块感、粗糙结构和颗粒/界面遮挡；视觉质量未验收。插件工具状态、回归数和源码审查都不应成为成品质量的替代品。

### 5. 工具API有可降低的摩擦

离线入口探针：

| 模式/字段 | 实际结果 | 责任判断 |
| --- | --- | --- |
| diagnose_failure + taskId/stageId | invalid-stage-reference，运行层未调用 | 字段说明没有点明仅review_result，容易看成所有模式通用；错误码也未说明如何纠正。 |
| diagnose_failure + currentResult | invalid-current-result，运行层未调用 | currentResult的仅improve_result说明明确；我误用是执行者错误，不应全怪插件。 |
| diagnose_failure仅正常字段 | 到达审计假的runtime | 无网络或真实模型调用。 |

判定在 [模式校验](../po06/lib/advisor.js#L268)，说明在 [工具参数](../po06/lib/advisor.js#L62)。贡献不应修改验收阶段，这个边界正确；应改善可发现性和错误提示，而不是放开错误模式。

### 6. 发现了独立的用量记账缺口

[工具回退](../po06/lib/index.js#L808) 在第一轮工具回答不是所需JSON时，进行第二次无工具调用；返回只带第二次usage。离线夹具两次分别5和7，实际12，返回7。这个是明确会影响成本判断的代码缺口，本轮仅复现留档，未改行为。

本次开发协作的日志还有5条已报告用量却outcome=superseded-input、packetChars=0的优化记录。不能单凭这个码判定是插件竞态、用户改口还是提交绑定差异；但未送达调用应与已送达调用分账，新输入应及时取消旧工作，而不是仅在写入时阻止旧结果。

### 7. 不应把所有困难归给插件

我反复错误锚点编辑、误删相邻代码、工具脚本语法错误是我自身执行失误。已有工具schema或注入的要求可能增加摩擦，但不能据此断言它们导致了这些错误。原会话sandbox对IPC的限制属于宿主政策；本次审计权限更宽，不能拿成功截图证明原环境也能截图。

bash的非零退出、受管进程收尾和原样参数通道有帮助。低成本软提示见 [工具诊断](../po06/lib/bash/bash-diagnostics.mjs#L79)，明确说需要真实渲染时保留浏览器，并未禁止浏览器；“重武器/更便宜”的措辞可能过度强调节省，但目前没有因果证据证明它造成替代验收。应保持结果证据的重要性，不能把成本建议变成对方法的否定。

本轮尝试整份开发档案解压统计超过run_code内存限制，是我的读取方式问题；统计未完成，不纳入量化结论。两个较小自然任务已完整读取。

## 改进优先级

| 顺序 | 通用改进 | 对执行AI的实际收益 | 成本边界 |
| --- | --- | --- | --- |
| P0 | 将完整建议与未完成诊断清楚分开；保留思考在可查看诊断/UI中，明确其不是已验证改法 | 不会因“有专家文字”就照改，没有图像时知道只能得到源码假设 | 用已有状态，无新增模型；不丢诊断记录，不硬禁止以独立证据确认后使用其中的线索。 |
| P0 | 让证据说明能对应最终版本和实际执行路径；将运行、仿真、源码、画面各自的证明范围说清 | 我能直接知道哪个原目标已验证、哪个关键路径根本没跑 | 机械可核对的路径/版本复用现有字段；无法机械证明语义覆盖时如实标未知，不新增全面验收流水线。 |
| P1 | 当前建议跟随进展：长期目标保留，重复方案与不相关旧阶段不持续前置，变化只更新相关提醒 | 少筛选、少解释同一状态，更容易回到实际成果 | 不按硬字数裁掉长推导；完整记录保留按需查看，状态更新不调模型。 |
| P1 | 优化角色收敛为补关键缺口与高价值内容，原话的否定/决定不能被更严格转述替代 | 我得到新增能力，而不是第二个项目经理规定整套实现 | 不新增筛选模型、不埋领域规则、不替用户更改模型/思考档位；不再继续同题微调到样本好看。 |
| P1 | 聚合所有已执行调用用量，区分送达/丢弃/回退；按真实提交身份取消被替代工作 | 能判断等待和额外调用值不值得，减少真正白跑 | 属于运行/记账改进，不能用token多少评分成果质量。 |
| P2 | 在工具描述、校验错误中点明模式限制和最小纠正方式，阶段只服务真实依赖 | 少学规则、少重试；贡献与验收不会混用 | 不加更多常驻说明，不要求每题三种咨询都走，不强制采纳登记。 |

我的优先选择是P0两项与P1当前上下文/成本问题。先让帮助可使用、证据可判断、开销可看清，再评价优化器能否稳定给有效内容。不是继续把每个观察写成新规，也不是把复杂材料盲目裁剪。

## 应保留与应停止追逐的东西

保留：原话可追溯、英文保真和字面恢复、版本/范围/取消隔离、工具执行结果可靠、用户已有设置、独立具体构造、keep和无增量合法、建议不等于验收。

停止作为成功指标：常识覆盖更多、参数更多、思考更长、条数更少、顾问调用率更高、阶段通过更多、测试数量更多。这些都可能与成品质量同向或反向，必须看实际结果。
