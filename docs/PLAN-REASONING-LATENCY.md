# 实验推理：方向交给原模型取舍

> 本文件保留 v3 的历史方案与当时实测。当前实验实现已转为 [v4](INFERENCE-V4-IMPLEMENTATION.md)，方向档位、预算和真实证据背景以该说明为准。

本地分支 `experiment/reasoning-latency-1`。发布版 `v0.8.4-stable` 未改、未发布此候选。

## 当前实现

用户修正了前一版思路：择优只需简短思考方向，不必先生成多份完整实现，也不需要独立裁判。现在 `parallel` 的流程是：

1. 同一工作模型并发生成 2～3 份简短的方法提要，不提供工具；方向请求有独立 1024-token 上限，不要求 JSON 或内部推理过程。
2. 将所有可用方向作为插件来源的可忽略建议，追加到派生工作请求。工作模型结合原任务自选、组合或全部忽略，直接执行，不提交择优报告。
3. 原工作模型保留原始 provider/model、reasoningEffort、maxTokens、完整消息对象/原生 replayState、工具及会话 ID。逐 chunk 实时输出，不缓存完整实现供裁判挑选。

`hybrid` 额外轮次只在执行前改进方向，不改完整实现；fast 为零额外方向轮次，balanced 最多一轮，inherit 保留请求轮数。纯 `loop` 是独立的完整回复反馈模式，本轮保持原行为。

短方向使用模型目录支持的轻档：fast 在支持 off 的 Flash 路由使用 off，balanced 使用 low，inherit 仍按用户请求。只轻量化方向，不降低实际工作生成强度。

## 边界与可观察性

- 所有方向都传入，不伪造原模型选中了哪一条；trace 区分 `direction`、`direction-refinement`、`working`，交接不是验收。
- 方向若无正文、工具提议、代码块、过长、生成中断或相同正文，会记录并丢弃/去重；全部不可用时只恢复一次原工作流。
- 方向的 provider reasoning/replayState 不进入交接，仅传正文；历史工作消息与其 provider replayState 保留原对象，不改写冻结请求。
- 原工作流开始后异常直接交回宿主，绝不重新生成或重放工具。取消原请求仍生效；停止额外思考可恢复普通生成，开始实际工作后关闭增强不再中断工作。
- 新计划分别记录额外调用、实际工作调用及上限；调用次数上限不等于服务商墙钟时间上限。

## 实测与限制

真实模型测试只有 `deepseek-official/deepseek-flash`。预先固定同一 Node ESM 区间合并模块任务、原请求/工具/low 档位/4096 主输出上限，各输出一次，不手改成品：

| 观察 | 流程 | 用时 | 已报告总 tokens | 行为检查 |
|---|---|---:|---:|---|
| `0f6659d` 旧基线 | 2 份完整实现 + 1 裁判 | 10.158 s | 6008 | 18/18 |
| 方向 v1（保留） | 2 份 low 方向 + 原模型；其中一方向 max-tokens 无正文 | 11.329 s | 3821 | 18/18 |
| 方向 v2（修正方向角色档位） | 2 份 off 方向 + 原模型 low 执行 | 6.745 s | 2813 | 18/18 |

v2 两份方向均有正文（332/770 字符），约 1.845/2.161 秒，均无工具；实际工作约 4.576 秒，只交一份实现。记录和原始工具产物保留，见 [观察记录](evidence/REASONING-DIRECTIONS.json)。

这是一次受控小任务与一次有实质改动后的观察，v2 属于针对 v1 预算耗尽的修正后验证。不能据此宣布稳定 34% 提速、所有任务质量等价或必然降低费用；tokens 是服务商报告，非实际账单。

局部回归覆盖方向交接、无裁判、原生流/消息、工具边界、取消/回退/关闭开关、旧循环与设置兼容。103 个非浏览器套件执行退出成功；浏览器依赖的 `verifier-html.test.mjs` 前轮已超时，本轮不把它算通过，也不宣称已在现有 GUI 实际激活。

## 对此前分析的更正

前轮把整个运行（包括串行反馈、修订、择优）的 Σ调用时长/墙钟比率写成“候选并发宽度”。这个量不能证明候选串行；`loop` 只有一份初始候选，比率接近 1 本来就是预期。已改为只统计初始候选阶段。128 条历史 trace 的分组延迟只能作描述，不同组的 provider、上下文、任务均不一致，不能构成因果提速对照。

前一版只限制轮数的本地提交 `0f6659d` 仍可回退；其“fast hybrid 无修订即完整候选择优”的方案已被这次用户决定取代。
