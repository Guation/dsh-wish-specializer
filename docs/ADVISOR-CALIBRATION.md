# 顾问触发校准与 Flash 小样本记录

状态：本地实现与定向回归完成，开发修订 **advisor-calibration-1**。运行实例最后核对仍为 stable-quality-1，需重启并刷新现有 GUI。本记录没有证明生产调用率提高或通用质量提升。

## 这次改了什么

- 重要策略/结构选择、明显取舍或较大返工代价：方案锁定前主动获取 develop_approach，不必先卡住或证明现方案有缺陷。
- 实质设计、推理或实现的初版：主动取得 improve_result 的独立观察，即使自己满意；无实质收益允许 keep，不强造修改。
- 重要正确性、返工代价或复杂依赖的交付：原始证据和自验之后做 review_result；improve_result/keep 不代替验收。
- 普通讨论、确认、简单直接可核对的小改动直接完成；当前版本已有独立覆盖不重复咨询。不要求每轮/每步调用，也不要求把三种用途跑遍。

规则在 [共用触发模块](../po06/lib/advisor-invocation.js) 定义，被中文/英文协作指引和工具描述复用。优化器的可选 consult 也移除了“必须已有未解决瓶颈”的前提。旧默认核心按精确哈希迁移，真正自定义核心保留。工具/优化日志增加 advisorInvocationRevision，便于后续按真实修订区分调用记录。

没有新增调度模型、自动咨询、强模型兜底、固定循环或配置开关；现有贡献/验收的结果含义不变。主执行模型仍决定实际调用，提示词不保证模型遵守。工具描述去掉重复规则后为697字符；中文/英文工作指引为1264/2206字符，三个中文优化档位为736/734/771字符。

## 工程验证

19份定向离线测试文件，node --test 汇总 **167通过、0失败**。新增校准集验证实际工具描述、工作注入入口、关闭辅助的豁免、日志修订及旧默认/自定义兼容。其余覆盖材料角色/版本、会话隔离、英文回退和验收边界。不是完整CI或真实UI交互验收。

独立复核最初返回assist-off；会话后来恢复可用后，三次代码专项复核均使用Flash。最新模型报告将S1.K1–K3全部标为satisfied，但宿主因证据范围保护仍返回unverified / reviewPassed=false，**未取得正式阶段放行**。没有修改会话设置来强行开启顾问。

首次材料中我遗漏了日志的仓库前缀，导致缺证；补证包过大曾被截断，随后缩小。复核还暴露了材料登记与范围保护的开销：同文件多次读取会占用材料名额，附加证据或历史截断可能使已确认的局部结论无法放行。本轮没有绕过这些保护，不再为同一结论继续重复模型复核。

## 实际产物对照：三个领域，全程 Flash

原始材料与模型最终输出见 [结构化证据](evidence/ADVISOR-CALIBRATION-FLASH.json)。主执行、顾问与落实均用 deepseek-official/deepseek-flash，reasoningEffort=low，每次最多8192输出token、120秒。先让Flash自行产生初稿，再明确请求一次真实 improve_result；有完整建议时让同模型落实。没有为了让顾问成功而人为埋错。

| 样本 | 顾问结果 | 实际观察 |
| --- | --- | --- |
| 区间合并代码 | keep，约10秒 | 初稿18项行为/不改输入检查通过；保持原稿，没有强造修改。 |
| 分组成功率分析 | suggestion，约14秒 | 初稿六个主要成功率均正确，但解释把90/330写为55%。顾问独立指出约为27%，后续同模型落实。局部算术纠错有证据；不能外推整体质量或因果结论正确。 |
| 故障公告写作 | 无完整答复，约53秒 | 初稿满足已核对的时间、上传问题、反馈入口和字数要求；顾问思考占满8192输出token上限，没有完整JSON。保持原稿，未证明写作收益。 |

数据样本的原始表述：

~~~text
only 55% of A cases are easy (90/330)
~~~

落实后的表述：

~~~text
only 27% of A cases are easy (90/330)
~~~

独立算术核对：90/330 = 0.272727...，约27%。检查中的表面格式/主要成功率分数并未捕捉这个解释错误，因此不以“8/8”之类计数冒充质量提升。写作的事实蕴含、清晰度和语气仍需人工看原文。

旧/新英文工作指引使用相同Flash、相同状态、相同中性工具定义。最终有效探针都用 reasoningEffort=off、最多1536输出token；只观察真实工具提议，不执行这些提议。该档位与上面的产物实验分别记录，不混用。

| 当前状态 | 旧指引 | 新指引 |

| 重要结构选择、未锁定方案 | develop_approach | develop_approach |

## 测试有效性与资源记录

第一批设置包含输出上限过小和样例占位语歧义，保留为无效设置记录。工具选择探针最初缺少宿主要求的assistant source元数据，在本地序列化前失败；这些不是Flash拒绝咨询。补齐契约后才得到有效工具提议。检查器的空白匹配/时间匹配错误已离线更正；分析任务的decision枚举有歧义，描述性选择A且明确说明因果不确定时不判错。没有重跑产物来挑选更好的结果。

小样本及入口调试累计真实计量请求 **25次，71,750 token**，全部Flash；包含极小路由检查、设置调试、输出不完整的尝试及两轮选择探针。此用量按适配器返回的totalTokens计，包含缓存读取。失败的本地工具消息构造不计作已发生的模型请求。生产成本是否下降没有测试结论，也未改用户思考档位或输出设置。

另有三次现场独立代码顾问调用，包含多轮只读查证，报告用量合计 **254,268 token**；本轮全部已报告用量合计 **326,018 token**。这里的顾问调用数不等于底层模型请求数。额外用量与形式性补证一起留档，不将其包装成低成本增益。
