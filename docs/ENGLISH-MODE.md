# 英文模式使用与边界

在当前会话“优化选项”中开启“英文模式”，默认关闭，按会话保存，设置页也可设全局默认。界面保持中文。不添加答复语言机制：模型按英文输入正常工作；原话明确“答复使用中文”等要求，会忠实翻译给模型。

英文模式转换当前用户任务、本插件优化策略、解释输出及辅助标题，不生成额外风格段或尾注。内置策略有静态英文版本；用户自定义解释提示词不被覆盖，生成缓存英文副本。辅助开启时同一次解释返回英文任务与英文辅助；辅助关闭时只调用轻量翻译。已是英文或纯代码/字面量的输入无需单独翻译调用。

原话保留在审查面板和语言来源记录中，不覆盖原文件；实际发送的英文任务独立显示。机器要求条目的来源quote仍引用原话，英文摘录另存，不以译文增加权限。代码围栏、行内代码、路径、URL、JSON、数字及明确逐字文本用占位符保护并恢复。机械检查只能证明这些内容没被改坏，不能证明自然语言含义百分之百等价；请直接查看译文，必要时选择“按原文发出”。

自动权限下完成后发送英文；审查权限下等待你确认，能看到原文、英文任务、英文辅助。取消保留输入框原话、不发送；按原文发出和跳过保留原文路径。斜杠命令留给宿主，附件对象不变。英文模式与提示词辅助、推理增强独立，切换辅助档位不丢英文设置。

现有历史、文件/工具结果、引用原文以及其他插件的文本不整段翻译。本模式不重写宿主冻结请求，也不承诺整份上下文全英文；首版覆盖GUI发送前转换和本插件模型侧指令。直接绕过GUI发送的API/CLI不会由前置拦截自动翻译。

英文任务与辅助建议分别校验，作为同一运行的最终结果保存。字符串和 `{id,text}` / `{question}` 建议先统一规范化，再处理英文和受保护字面量。有效零辅助直接完成，不等待非空内容；格式失败或必需的英文转换失败明确记录为失败，原始输出保留供诊断，不删光条目后伪装成功。已有保真翻译工具的校验和传输重试仍在其内部；优化产线本身没有第二套解释、占位或旧编译兜底。自动权限失败时只经统一的无包提交发原文，审查权限停留等待选择；跳过始终逐字发原文，取消始终不发。完整运行与验证边界见 [优化生产管线契约](OPTIMIZATION-PIPELINE.md)。

效果对照应使用相同模型、档位、任务和其他开关，在新会话比较英文模式开关。语言模式本身不代表能力提升已测，不必增加大范围跑分。
