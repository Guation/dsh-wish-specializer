## KI-1 · 自动 + 硬邦邦：切走再回来，发出去只剩一个壳

- **状态**：OPEN（2026-10-23 记录）
- **现象**：自动模式 + 协作基调=硬邦邦；发出消息后**切到别的会话**等优化跑完，再切回来把消息发出去，
  注入文里只有基调块（“老哥们…”），**没有【要干的事】/【自己搭的临时脚手架】**，也就是只有壳没有包。
- **为什么可疑**：基调块是**取用时**才加的（`applyFramingToPacket`），包是**存起来的**（`getIntentText`）。
  两者来源不同 ⇒ 很可能“包的写入/读取按会话绑定”，切会话后读不到包，但基调块仍按当前 framing 加上去。
- **要查的点**：
  1. `pendingCardBySession` / `intentBySession` 是否随切会话被清或错绑；
  2. 优化完成时写包用的是哪个 sid（是不是发起时的 sid，而回来时是另一个会话对象）；
  3. `getWorkingText` 里 `hasPacket` 判定在“切走再回来”这条路径上是否真的为 false（应打印实测值）。
- **验收**：切走再回来发出去，注入文要么完整（壳 + 包），要么**完全没有**（包为空时零注入）；不允许只有壳。

## KI-2 · 「以后不再显示」仍会重新弹出

- **状态**：调查中（2026-10-23）
- **现象**：提示弹窗点过“以后不再显示”后，重启 DSH 仍会再弹一次。
- **已排除**：
  - 写盘链路正常：`POST /po06/api/notice {forever:true}` → `200 {ok:true}`，`po06.json` 里确实写成 `true`；
  - `writeSettings` 是 **merge** 语义，正常保存设置不会把它冲回 false；
  - 客户端 `dismissNotice(true)` 走的就是 `POST /notice`，路径正确。
- **当前假设**：标志被**别的写入路径**改回 false，或用户点击时那次请求没到达（网络/静默失败）。
- **下一步**：在 `/notice` 与 `/settings` 两处写入后各记一条 wire 日志（含写入前后该字段的值），
  重启后直接看是不是有人把它翻回去。
- **验收**：点“以后不再显示” → 重启 → 不再弹；且台账能证明没有别的路径改写该字段。
