# 优化输出协议 v3

本页只定义模型输出与规范化。生产生命周期、渲染和提交见 [OPTIMIZATION-PIPELINE.md](OPTIMIZATION-PIPELINE.md)。整体重构已完成本地自动验证，现场复测待进行；旧版测试通过记录不代表本次生产流程已通过验收。

## 最小结构

```json
{
  "intent": { "text": "本轮意图", "relation": "continue" },
  "add": [
    "一条有价值的制作方向",
    { "id": "a1", "text": "另一条制作方向" }
  ],
  "scaffold": [{ "id": "s1", "text": "值得复用或临时构建的工作能力及其目的" }],
  "ask": [{ "question": "确实需要用户确认的问题？" }]
}
```

| 字段 | 规则 |
| --- | --- |
| `intent.text` | 非空的本轮机器理解；不替代原话，不增加用户授权；模型回 `intent` 字符串和顶层 `relation` 时忠实归一化并记录 warning |
| `intent.relation` | `new / continue / uncertain`；明确换任务才用 new，不明时保持 uncertain |
| `add / scaffold` | 制作/临时脚手架建议；数组项可为字符串或 `{id,text}` 对象 |
| `ask` | 只提供必要问题；字符串、`{id,text}` 或 `{question}` 均可规范化 |
| `clarify / decide` | 同一 v3 规范化入口保留的辅助字段；分别归入制作方向/待问问题 |
| `englishTask` | 英文模式的忠实任务译文，与建议分开；原话和精确字面量独立保留 |

没有内容的建议数组留空或省略，不为栏目制造内容。合计 3000 token 为制作、脚手架与 Ask 的预算上限，不是条数或填充指标。

## 一次规范化

字符串与 `{id,text}` / `{question}` 表示同一类文字，混合数组中的有效条目须完整保留。模型提供的 ID 可保留为来源引用，运行与用户来源身份仍由宿主管理；对象形式不能成为拒收有效建议的理由。

缺失或空的可选内容不使整份有效结果作废。无法使用的可选条目记录诊断，不凭空补正文；若提供的内容全部非法，或必需结构、请求真正失败，则返回 `failed`。只有机器理解、没有建议和问题时是有效 `empty`，packet 严格为空。旧 `ops`、reducer 补丁或 compiler 产物不作为生产失败时的备用协议。

结构解析与规范化依据字段和类型，不用正文正则判断“有没有像建议的内容”；空增量不触发 `retryEmpty` 或占位回填。具体失败与同一运行保存规则由主契约定义。

## 统一渲染

最终包按有用内容呈现制作、临时脚手架与 Ask 三类，空栏目省略。语言与正文在同一渲染入口确定；取包、注入和卡片复用最终文本，不添加风格包装或尾注。

问题字符串完整保留（包括 `a|b` 等字面量），不再解释旧的竖线分隔格式。对象只提取 `text` / `question`，不自动采纳 `options` / `assumption`。建议供工作模型优先考虑，不覆盖用户要求；提问不等于已经问出或获得同意。任务翻译与辅助各自保留来源，不能把机器建议混入实际 human 任务来增加授权。
