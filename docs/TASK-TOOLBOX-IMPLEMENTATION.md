## 第一轮实现

- 新增 [toolbox-proposal.js](../po06/lib/toolbox-proposal.js)：none/reuse/build/inspect，独立版本 1；能力、反馈、首次用途及停止扩建条件是方向性提案。无内容时不注入，不按建模关键词路由。
- 新增 [toolbox-context.js](../po06/lib/toolbox-context.js)：按 sessionId 获取真实 agent 工具表；全局回落只算 partial，失败算 unknown；注册事实不冒充运行可用或模型图像能力。
- 提案从输入与输出协议经过解析、pipeline、当前工作上下文和 capability 存档完整传递。toolbox-only 指有效 intent + toolbox，不需要为了发包伪造状态条目；noStatePatch 与 zeroAddition 分开。
- 提问动作在前、工具箱工作方法居中、原话与成品方向建议在后；现有 ask 及用户技术路线保留。
- toolboxMode 支持 auto/off、全局及会话覆盖，当前代码默认 auto；仅在原有 assist 开启时进行按需判断。它不自动搭工具、不增固定模型轮次，顾问关闭不使它关闭。auto 的默认是本地候选决策，P4/P5 再依据效果收敛；不改用户配置文件。
- 新设置进入 policy 与包形状失效，关闭不会保留旧工具箱包；可选字段损坏仅丢弃该提案，原始请求、补充与 ask 不连坐。
- 中英文处理保留工具箱自然语言字段，翻译失败只丢可选提案，不损坏保真任务；自定义提示词核心不覆盖，主工具路径和无工具回退共用扩展契约。
- 记录实际请求的 task-toolbox-1 提示词版本、启用模式及能力摘要，方便后续核对是否加载。

3. 新采集器的会话范围、查询失败、全局回落、空表与坏表已用直接集成测试核对；生产当前实例是否加载新实现仍待 P5 实测。

## 第二轮：真实开发闭环与耐久索引

对应[受控试点结果](../po06/experiments/task-toolbox/RESULTS.md)和[实际工具输出](../po06/experiments/task-toolbox/evidence/observed-results.json)。

- 工作模型真实创建了可重复调用的 Three.js workshop，首次检查并读取初始图片，然后用同一 edit/inspect/capture 入口完成两次修正；全部参数、三个版本与截图保留。轮组间距由约 -0.36 变为 0.04，尾翼单侧外伸由 0.75 变为约 0.075。
- 图像由隔离 Edge 的真实 WebGL framebuffer 返回并被本会话工作模型读取。两次初始 CDP 超时如实保留；第三次对受控浏览器调整 no-sandbox 后成功，不修改宿主或日常浏览器设置。试点启动的五个浏览器进程已核对全部退出。
- 最终独立 HTML 与捕获版本字节相同，阻断 HTTP(S) 后仍可用 file URL 加载；当前是简化概念车辆，不宣称写实质量或驾驶交互已验收。
- 新增 [toolbox-state.js](../po06/lib/toolbox-state.js)：宿主持有稳定 taskId，profile/session/workspace 隔离；调用开始绑定任务，旧任务晚到只归原任务；支持拦截→人类消息 ID 映射、pending 缓冲、取消和独立原子存档。
- 实际调用与工具自报信封共同形成历史记录，successCount 表示不同调用返回 reported-ok，不代表成品通过。非零退出、超时、取消和失败作业覆盖自报 ok；图像路径不自动记成已观察。
- 后台 pwsh/promoted 作业通过已观测 jobId 关联后续 job_output，原始任务/执行 callId 不变；分段输出可合并，重复回传不重复记账。
- 新增 [toolbox-facts.js](../po06/lib/toolbox-facts.js)，将相关工具入口、最近版本和反馈引用投影给工作模型；同一索引也进优化器 capabilitySummary。用户审查过的注入文字保持原样，不自动把删掉的历史再塞回去。
- [真实 stdout 集成入口](../po06/experiments/task-toolbox/check-integration.mjs)使用实际 CLI 输出调用生产处理函数并重新打开存档；事件信封与解释器为测试构造，明确不冒充当前 DSH 会话自然事件。

本轮定向检查：15 项 store 测试 + 19 项 toolbox/adapter 测试通过。全量首次为 134 / 134 套件、1411 断言通过；最后补充 native 进程 JSON 的非零 exitCode 用例后，最终为 134 / 134 套件、1412 断言通过、零失败。
