# 交付面：预览、发送与卡片

本页描述 [优化生产主契约](OPTIMIZATION-PIPELINE.md) 在界面上的表现。整体重构已完成本地自动验证，以下行为的现场复测仍须核对实际加载版本；不沿用早期迷你窗探针通过数作为本次验收。

## 一份结果，三个交付面

发送前优化绑定发起会话及本轮 `runId`。流式文字只表示进度；最终预览来自该运行完整结果中的 packet。上下文注入与辅助卡片使用同一份最终包，不能取用时再加基调或重新编译。正文为空时三个位置都没有辅助外壳、占位或卡片。

原话保留在输入/来源记录中。英文模式下，审查同时区分原话、实际发送的英文任务与英文辅助；机器建议不成为原话的一部分。代码、路径、精确文本和用户指定答复语言的语义保持。

## 确认、跳过与取消

| 操作 | 界面与提交结果 |
| --- | --- |
| 自动完成 | 取得本轮完整终态后，通过统一发送入口提交本轮 outgoing 与最终包 |
| 审查确认 | 展示本轮结果，明确编辑后确认；通过相同入口提交同一 `runId` 的最终文本 |
| 切回会话后发送 | 恢复该会话的完整结果，而非只有一段字符串；使用原 `runId` 和相同入口 |
| 跳过 / 双击 Enter 跳过 | 中止并清空本轮辅助；一次 skip 决定后逐字发送原话，英文模式也不改变这条语义 |
| 取消 | 中止并清空本轮辅助，保留输入框原话，不发送消息 |

自动、审查和恢复提交统一使用 `POST /po06/api/packet {runId, disposition: "send", …}`。跳过使用一次 `disposition: "skip"`，不能先清包又由观察者重开优化。取消只结束本轮、不提交消息。发送不依赖 `GET /packet` 的 15 秒等待/轮询。

`empty` 是有效的零辅助结果，不自动重试；有效英文任务仍可作为 outgoing。`failed` 显示真实错误，不把标题、基调或编译占位当成成功内容。用户明确重试时开启新运行，同会话旧结果随即失效。

## 会话与迟到事件

切换页面会话不改变任务的所属会话，也不取消后台生成。完成时完整结果保存到发起会话，回来后恢复来源、终态、outgoing、packet 与 `runId`。同会话的新输入替代旧运行；取消、跳过或被替代后，迟到的 SSE 完成事件不能重新填包、生成卡片或提交消息。

卡片只展示实际提交的辅助内容；观察者只消费该次明确提交的结果。判断一致性时比较同一运行的最终预览、注入和卡片正文，不能仅看字符数、HTTP 成功或“committed”。
