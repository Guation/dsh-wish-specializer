# 最近两个真实会话：顾问为何未形成稳定质量增益

## 结论与边界

当前服务端已返回 **round305-baseline-1**。最近两任务的持续上下文也包含恢复后的完整中/英文协作指引，顾问贡献修订为route-a-1。没有证据支持继续把问题归咎于“还是旧实例”。但这只说明代码/指引基底回到所核对的历史，不等于模型权重、所有配置和实际产物水平复刻了当时。

用户感觉顾问作用不足有真实依据，但这两会话不能概括为“几乎没采纳，且都把待验证明确判通过”。准确分解是：**调用晚、目标与证据错配、贡献落地但增益未证、未闭合复核对最终交付约束薄弱**。中文直接完成姿态尤其明显；英文虽以Done开头，却明确保留了核心未验证，不能混为完全隐瞒。

本轮只分析、保存证据和跑零网络的机械探针；未改生产源码、策略、模型、权限，也未修两个作品。以下是拟议路线，不是已经生效的机制。

## 一、两会话事实

按原始日志实际完成时间，最近两个HTML任务是59fb9fb9与288e64ea，均为单轮长任务。来源是原始多帧日志，不是只看最终答复；两份解码均零解析错误。公开工具/交付证据见 [证据链](evidence/RECENT-TWO-ADVISOR-CHAIN.json)。

### 中文：不是没改，是修复与验收脱节

- seq51自建阶段把米制数值、等弧长算法、轮组和楔形炮塔定成检查点；这些具体值与实现选择不是用户原话。开放目标“极其精细、真实、写真”的主要效果要求未完整转化成可观察结果，检查表反而围绕主模型自己的方案。
- seq406提交源码和4张真实运行截图，geometry验收却把源码排除，禁用读工具；顾问同时被问精确米制尺寸、等弧长算法、轴线和轮组。这一材料组合本来就无法证明部分问题。
- 顾问并非只说待验证：findings指明侧裙骨架、炮管竹节、外伸板、轮廓等问题，给了可执行改法；报告1满足/4未验证，0 failed，说明可见问题未进入相应的失败检查点，信息与状态分裂。
- seq417、419确实落地12处几何修改并重拍，无异常。主模型也以实际尺寸9.62m反驳顾问“约11m”的透视推断；有证据不采纳合理，不能要求照单全收。
- 但没有同对象复核，seq460把旧截图复制到交付名后删除原.tankbuild。seq467的持续上下文仍4 unverified、1 stale，明确证据缺失/版本变化。seq478却“做好了”，只说采纳了哪些，不披露未闭合验收。

### 英文：贡献有效但没证明视觉收益；未验证有正当部分

- seq424的improve_result读源码后贡献composer像素比、景深计算、材质与镜头等具体内容。seq433～504的实际编辑表明这些不是口头采纳。**采纳数不能等于质量增益**，因为没有浏览器像素前后对照。
- seq564要求由源码验boot/首帧/控件/后处理的真实运行；没有相应执行，6项未验证正确。不能为让顾问更“有用”强迫它通过。
- 浏览器探测失败原因没有被正确分层：最初在工作区外写文件被拒；后续启动无截图/超时，有工具结果sandbox.denied:false。主模型把这些合并为“沙箱不允许浏览器”。中文在同环境通过工作区profile与CDP拿到了图，这说明至少不能把英文失败直接当作机器绝无渲染能力，也不能归因为语言本身。不能绕过真实拒绝，正确做法是区分边界拒绝、启动参数、进程等待、运行错误。
- 顾问怀疑CTRL未guard，但所读范围不含真正的setMode定义；主模型读到2041的if(CTRL)排除了该疑点。这类没追到判定点的警报会消耗注意力，使真正缺口更容易被当作“又是保守意见”。
- seq604有Done开头与大量功能介绍，但明确“not one pixel… addon/boot/first frame unverified”。报告状态和最终文字没有伪造pass；不足是完成姿态在前、核心缺口在后，可能弱化缺口的显著性。这是呈现与完成口径风险，不等于已证明其隐瞒或将缺证判通过。

## 二、全局根因

### 1. 独立贡献来得太晚，且优化器并非可靠事实源

两会话都有早期优化补充，但都没有真正围绕重大未决策略调用develop_approach。中文唯一咨询是在大部分工作做完后；英文也在成品基本完成后才改材质/后处理。它们比较擅长找局部补丁，无法证明已经提升了整体构造与表现上限。

这不意味着所有任务都必须早咨询。这里的关键是复杂、高审美目标、许多不确定实现选择，存在值得独立探索的节点；这个节点没有转化成实际独立贡献。再加一句“记得咨询”不会自动改善。

优化建议本身也会误导：中文包把完全离线单HTML说成必须第二文件，这是不成立的全称；英文包反而承认可以内联。具体知识可能有错，不能把补充或自选设计静默升格为事实和验收目标。**顾问应有机会挑战这些关键前提，而不是只审主模型完成的清单。**

### 2. scope在替证据类型作决定，检查点却横跨类型

当前 [scope策略](../po06/lib/advisor-scopes.js#L16-L46)让geometry/appearance验收images-only，贡献模式可混合。原目的——不让源码自证画面——正确，但实现成了“视觉验收看不到用于算尺寸/验证算法的源码和运行指标”。同时一个stage却含尺寸、观感、算法，注定产生大量缺证。

应当约束的是**某种证据能证明哪条主张**，不是“属于一个scope就删掉另一种材料”。允许必要源码/指标，并不意味着源码能证明真实像素。

### 3. 把包不完整扩大成结论不完整

约126KB文件默认先送前16000字符，常是CSS/HUD；顾问再消耗多轮读关键范围。[limited分支](../po06/lib/advisor.js#L388-L393)又因任意材料截断/历史省略把整份pass降级；[reviewOutcome](../po06/lib/advisor-outcome.js#L5-L24)也把材料级gap当整体gap。

零网络探针 [结果](../.po06-tmp/claim-evidence-probe-result.json)直接证明：同一首行静态常量，同一满足报告——附整文件（首行已见）时unverified，附line1时pass。这不证明未读依赖可以忽略；它证明局部可确定事实和全局未观察范围应分开。

英文顾问的6项运行未验证仍然合理，不能用此探针否认真实运行证据缺失。

### 4. 当前机制保住了状态，但没保住交付语义

[工具返回](../po06/lib/advisor.js#L431-L460)、[横幅](../po06/lib/advisor.js#L523-L535)、[状态计算](../po06/lib/advisor-outcome.js#L5-L24)都已经区分ok和reviewPassed，advance也会拒绝。两会话确实收到不通过横幅，中文最终前仍被注入未闭合状态。

但 [实际context入口](../po06/lib/index.js#L1789-L1794)只把状态发给主模型，相关字段没有自动约束最终答复/交付展示。非stage上下文还只显示前3条检查，缺口原因与最低有效动作不充分。这是“提醒型协作”，不是已建立完成声明闭环。不能声称再换字段名就能硬保证。

### 5. 质量采用与验收闭合是两条不同的因果链

“改了顾问建议”“运行没报错”“还剩待验证”被当作一串完成仪式。正确链应是：建议的可用依据 → 选择采用/试验/拒绝 → 实际新结果 → 是否获得原目标上的收益。验收则是：原任务关键要求 → 当前证据 → 结论与缺口。

**质量建议不应绑死为必须关闭某个验收check。** 一个已经合格的作品照样能被拔高；反过来，形式上所有check通过也不代表极致。主模型合理拒绝错误建议不应被统计成不合作。

## 三、建议的通用路线：先做三件事，不重建一套大流程

### A. 先修证据闭环：按主张组织材料和结论

- 同一复核先独立看实际成果，再按需要读实现/运行指标。各自结论标清“源码已核实／运行实测／视觉观察／推测”，不可互相替代。
- 调用前检查现有材料能否回答本次检查：可廉价补充的范围或指标优先补；若问题只剩缺运行环境，直接保留缺口与最小授权内行动，不再付费请模型重复“缺像素”。
- 读到可疑点要追到必要定义/guard/调用方再判断；不能查全则是有条件假设，不是确定缺陷。已可见的真实失败不能只塞findings、check却全待验证。
- 截断按被影响的主张传播。允许窄结论成立，保留未覆盖依赖和全局限制；不给原任务未证实的部分自动通过。
- 原任务结果要求与模型的实现选择分开。避免把自选常量、具体算法、功能数量当用户新验收目标。

优先做这一项，是因为它同时提高顾问意见的可信度、降低无效查证，减少执行者对“待验证”的习惯性免疫；不是放宽证据。

### B. 接通贡献闭环：在有杠杆处提出可试的实质内容

- 对当前关键未决选择而非整个工程重做规划。利用原始目标、实际条件与少量决定性材料，贡献可直接采用的构造/推导/内容，给适用前提与可反驳依据。
- 让高收益节点更容易进行真正咨询，而不是要求每阶段、每初稿必咨询；早期优化器已有有效贡献时不重复。晚期只改参数不应被默认当作发挥了全部顾问能力。
- 执行者只需处理影响当前结果的关键意见：采用后比较实际结果；不采纳给具体依据；无新证据/无收益可keep。不填全量采纳表，不按建议采用数量打分。
- 要求被选择的贡献咨询尽量给具体内容，不等于要求执行者必须采纳，也不等于顾问必须制造改动。[原始贡献协议](../po06/lib/advisor-contribution.js#L34-L45)明确允许无增益keep；保留这一边界。
- 优先小而有判别力的局部实验，自动保留相关改前版本/证据，不另加一套手工报告。无法观察收益时称“已尝试／收益待证”，不要叫“已提升”。

这是能力提升本体。不能只补交付闸门而让顾问继续当高成本验收员。

### C. 补上最小交付语义闭环：可交付不等于已验收

- 当前任务、当前成果版本上，把已知失败、核心未验证、可选优化清楚区分；非阶段调用也适用，不强迫所有任务先注册stage。
- 已知核心失败应先修复或交付有缺陷版本；关键缺证应补证，实在无法则交付待验证版本；可选拔高不阻塞。用户若明确接受限制，记录为授权选择，不伪造测试通过。
- 宿主可在交付卡/最终展示附机器计算的状态与关键缺口，避免全部由模型一声“Done”覆盖；不删除答复、不阻断所有文件分享、不用自然语言关键词当唯一闸门。
- 不假定当前宿主已有最终响应拦截接口。实现前先核实真实扩展点；若只能注入上下文，就如实承认是软约束，不能承诺“机械禁止宣称完成”。
- 原证据被删或文件改版，失效相关结论，不抹掉问题；单纯复制成品不能自动把旧复核迁到新版本，也不能禁止有新证据的定向复核正常关闭旧项。

### 不建议

不再整树来回退、不叠加长期流程说明、不固定顾问次数、不强制全采纳、不把“全部unverified”当勤勉、不把没报错当极致、不用强模型悄悄替换路线A。

## 四、怎样证实这条路线有效

分开验证三件事：

1. **状态和证据正确性**：重放这两个案例。修改后自验不能清空旧顾问问题；原证据删除仅失效相关项；一个可确定局部主张不会因无关截断全盘降级；源码不能证明首帧；用户明确改任务/接受限制不被旧项困住。
2. **意见的实际作用**：新自然任务中，关键建议是否给了执行者原本没有的可用内容，是否改变了实际结果或有证据被拒绝。独立意见不保证正确，不以调用数/采纳数/引用数衡量收益。
3. **完整产物体验及代价**：同任务权限/可用工具/入口/provider/模型/推理档、最好包含中英文配对；保留全部失败，比较真实产物与关键路径体验、总用量/耗时。当前两任务的渲染路径和证据条件不同，不能当受控语言对照，更不能从两题估通用胜率。

本例三次顾问调用合计报告231458token（中文24917，英文206541）。这不是费用价格，也不含主模型全部工作；足以说明“再多问几次”不是无代价的通用解法。先减少必然缺证咨询和重复送无关头部，比规定更短的回答或强行少读更合理。

## 独立意见与未采纳项

一次独立Flash分析同样指出最后只靠模型自觉和贡献缺闭环的问题。它建议按“review版本早于当前版本”的项计算未闭合，并把每条改善绑到验收check；这两项不采纳：前者会漏掉同一版本仍未验证的项，且opaque标记不可直接按大小排序；后者混淆拔高与验收，并增加手工协议。保留其“交付状态应独立于注册stage、区分可补证/客观不可验”的有效方向。

独立复核承认具体采纳、两会话差异、源码/运行边界及通用性，但没有通过整份分析：英文原始证据在该次调用被16000字符预算截断；另把“要求顾问给具体贡献”读成“强制执行者全采纳”。前者是有效材料限制，本分析主线已读取完整原始seq604，不把截断复核视为完整覆盖；后者用原始协议keep条款及上文显式非强制边界澄清，不通过修改历史事实来迎合意见。原始复核与异议保留，不记验收通过，也不为pass重复模型调用。

这些建议当前尚未实施。历史基底已恢复这一事实与“已经找到稳定通用增益”必须分开；本报告提供下一轮最小实验路线，不提前承诺效果。
