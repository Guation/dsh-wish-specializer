# 当前执行计划：稳定骨架的通用产物能力提升

状态：当前试用候选 **advisor-loop-1**；核心目标仍为同弱模型的最终产物能力。见 [闭环实施计划](PLAN-ADVISOR-LOOP.md) 和 [真实结果/限制](ADVISOR-LOOP-RESULTS.md)。历史基底、失败与反例均保留，不用更严状态、测试数或一次探索叫通用提升。

## 1. 首要目标：最终产物更强

路线 A：主执行、提示词优化和顾问都使用同一个弱模型，利用更有效的信息、独立分析与具体贡献，提高最终产物的质量上限，争取在不同任务上接近或超过更强模型使用原始提示词的表现。

**以最终产物的效果提升为第一判断依据。** 能跑通、提示词更短、协议更完善、少调用几次、报告更完整，都不能单独算能力提升。代码回归只证明接线与既有行为正常。

本轮重点同时涵盖：

- 找出执行者忽略的问题、前提或关系，减少会损害产物的错误。
- 发现尚未利用的知识、方法、构造或表达机会，把已经合格的产物进一步做好。
- 提供工作模型能够实际采用的内容，让发现转化为成果提升。

不只追求更谨慎或少犯错，也追求成果的深度、完整度、创造性、可用性与完成质量；哪些方面重要，由当前任务决定，不套固定评分表。

资源消耗是实施约束：优先复用现有调用、材料和状态，避免无增益的开销。但不能为了缩短上下文或减少一次合理查证，牺牲决定成果质量的信息。真实收益与代价分别记录。

## 2. 已确定的研发边界

1. **只优化稳定骨架。** 不改多生成择优、候选集、循环推理、固定自我批评或其他实验性推理增强；不把它们包装成默认顾问流程。
2. **通用机制，临时判断。** 不把某个坦克、网页、文章或其他案例的成功经验写成行业专用规则。顾问依据当时的原任务、实际产物与相关事实临时形成关注点。
3. **中英文共用能力机制。** 两种语言同步实现、分别验证。接受实际表现差距，不以中文追平英文为目标，也不把差距当成插件架构失败。
4. **原意不扭曲仍是底线。** 目标、明确决定、否定和授权保留；建议不成为用户要求。当前不展开独立的意图系统重构。
5. **复用现有用途。** 强化 develop_approach / improve_result，验收仍由 review_result 负责，不新增一套顾问、强制打分或复杂状态框架。
6. **按收益决定咨询。** 不要求每轮、每项工具动作或每次修改都咨询；已有办法和材料足够时直接完成。没有实质改善机会允许 keep。
7. **同模型，不暗中兜底。** 不自动调用更强模型。若确需真实模型验证，只用已授权的 DeepSeek Flash；效果测试优先交给用户执行。
8. **保留已经修好的运行行为。** 英文任务翻译回退不再清掉有效辅助；保留取消、迟到结果、跨会话隔离、自定义提示词和旧接口兼容。
9. **本轮不处理 CI、不发布 0.8.4。** 当前计划不扩大为发布门、长时变异检验或基础设施工程。

## 3. 当前基线与真正待补的部分

上一阶段已有的能力包括：优化增量整合为解决路径、可选咨询机会、独立解题/产物拔高、当前与前版正文比较，以及短的本轮贡献提醒。实现和使用记录见 [路线 A 开发说明](ROUTE-A-QUALITY.md)。

这些能力已经存在，不重新造接口。下一阶段主要补足：

- 相关材料的选择与保留，避免顾问看错版本、漏掉关键事实，或受无关叙述影响。
- 顾问对当前产物的临时盲区分析，减少只重复执行者已关注问题的情况。
- 将分析转成局部可采用内容，并在正常多轮协作中根据真实变化更新它。

route-a-2 是上一阶段的文件修订基线。开始实施时必须重新核对工作树、实际加载标记与当前配置；文件标记、设置预览和真实请求记录分别看，不能假定运行实例已经更新。

## 4. 目标工作方式

~~~text
原任务 + 最新纠正 + 实际当前产物 + 相关事实
                       ↓
      现有顾问的一次独立、针对当前状态的分析
                       ↓
   有依据的遗漏/瓶颈/提升机会 + 可采用的具体贡献
                       ↓
       工作模型判断采纳，完成实际局部修改
                       ↓
  利用已有结果作必要比较；新事实出现时更新分析
~~~

这表示信息与贡献的流向，不是每个任务必须完整走过的流水线，也不是自动循环。

同一个模型的独立上下文不能保证发现所有盲区。机制应提高发现与修正机会，同时允许顾问误判、材料不足或无增益；顾问评分、自信和建议被点击采纳都不能证明产物变好。

## 5. 按顺序执行的计划单

### P1：把决定效果的材料送到顾问面前

- [x] 核对并改善当前任务原始来源、最新用户纠正、当前产物和相关证据的选取。
- [x] 区分原话、实读事实、执行者假设、尚未采纳的建议，以及当前/前版材料。
- [x] 优先保留会改变判断的材料；减少重复叙述和无关工具输出，不仅靠最近时间或文件名命中来代表相关性。
- [x] 保持现有预算与权限入口，关键材料不足或被截断时透明说明；不新增模型调用做通用历史摘要。

**预期效果：** 顾问能基于真实问题和产物作更好的判断，多轮纠正不被旧叙述盖住。

**进入下一步的证据：** 离线夹具证明关键来源、版本与证据正确传递；筛选不能将未读材料视为事实，也不能用前版冒充当前版。

主要入口：[顾问快照与执行](../po06/lib/advisor.js)、[材料选择](../po06/lib/advisor-scopes.js)、[材料准备](../po06/lib/advisor-materials.js)。仅在实际必要时调整 [会话上下文](../po06/lib/session-context.js)，不顺带全面重构。

### P2：在现有顾问中强化临时盲区分析

- [x] 以 improve_result 为主，先对照原目标独立观察当前实际产物，再比较执行者的假设、关注点或自评。
- [x] 让关注点由当前任务与材料临时产生；发现有实质影响的遗漏、错误前提、未利用机会或质量瓶颈时，说明位置/关系、影响与依据。
- [x] 在用户已授权范围内，允许指出与当前目标直接相关、但执行者 focus 遗漏的决定性问题；不增加新偏好、功能或验收目标。
- [x] 区分已观察的偏差、待核的假设和正向改进建议。证据不足时给最小查证点，不假装已经证实缺陷。
- [x] 对已有合格产物继续寻找值得实施的提升；没有实质增益就 keep，不为了体现顾问价值制造问题。

**预期效果：** 顾问提出执行者尚未充分利用的、有助于成果提升的观察，而不只是复述原方案。

**进入下一步的证据：** 当前产物证据、任务目标与建议能够对应；缺材料、局部材料和相反证据都可被正确表达。不能以顾问自评证明已经跳出盲区。

主要入口：[贡献协议](../po06/lib/advisor-contribution.js)、[顾问运行](../po06/lib/advisor.js)。复用现有模式与字段，避免新增评分体系或独立“盲区模型”。

### P3：把发现变成能提高产物的实际贡献

- [x] 对值得改善的问题提供可采用的局部内容、方法、构造或明确修改步骤，说明接入位置与收益依据。
- [x] 保留现版本的优点，检查修改可能导致的退化、依赖变化和额外代价。
- [x] 真正需要时直接贡献替换片段、推导或内容骨架；不要求每种任务都提供代码或同样栏目。
- [x] 工作模型判断并落实贡献，不只复述顾问意见；一般实现选择不额外转嫁给用户。

**预期效果：** 顾问的分析实际进入成果，减少“意见正确、产物没有变好”的断层。

**进入下一步的证据：** 接线测试确保贡献完整到达工作模型；效果实测另外记录采用了什么、改善了什么、有没有退化。

主要入口：[协作指引](../po06/lib/advisor-workflow.js)、[中英文协议](../po06/lib/english-prompts.js)、[贡献协议](../po06/lib/advisor-contribution.js)。只改必要指引，不继续膨胀优化器协议。

### P4：支持正常多轮更新与成果比较

- [x] 复用当前/前版材料与现有本轮反馈，明确观察适用于哪一版、什么范围。
- [x] 用户纠正、新产物或新事实出现时更新相关分析；旧盲区不自动套给新版本，也不持久化成用户要求。
- [x] 改进后优先利用现有结果作必要的新旧比较，不偏爱新稿、不仅凭推荐声称变好。
- [x] 已解决的问题不反复咨询；有真实新证据或实质未决点时仍可再次咨询。
- [x] 部分输出、超时、取消、并发或迟到结果不能覆盖当前有效状态。

**预期效果：** 一次有用的贡献能持续帮助正常协作，同时避免无收益的重复检查和修改退化。

**完成证据：** 版本、轮次、会话隔离与迟到结果的离线回归通过；没有新增固定咨询或自动修订循环。

主要入口：[任务与当前轮状态](../po06/lib/capability.js)、[顾问执行](../po06/lib/advisor.js)、[协作指引](../po06/lib/advisor-workflow.js)。

### P5：交付验证与效果对照入口

- [x] 中英文语义、默认/自定义提示词、实际工具枚举、客户端展示和英文回退均做定向回归。
- [x] 保存当前实现修订、原始回归结果、运行实例是否加载，以及最小试用方法。
- [x] 明确区分代码接线完成、运行已加载、真实产物增益；缺独立复核或效果数据如实登记。

**完成证据：** 已授权的稳定机制接通，定向回归无失败，交付说明可以直接用于实测。尚无效果数据时，不能声称通用能力提升已被证明。

## 6. 效果判断：始终看最终产物

首要比较是相同弱模型下，上一稳定实现与本轮实现的最终产物；另以弱模型裸跑、强模型原提示词裸跑作参考。原始任务、材料、权限与主要配置应可比，记录实际顾问调用及采用情况。

- 最终成果是否在当前任务重要的方面明显更好？
- 顾问是否发现了执行者没有充分考虑的实际问题或提升机会？
- 贡献是否落实，收益是否伴随退化？
- 提升能否迁移到未参与调试的任务，而不只发生在少数重复案例？
- 实际耗时、模型用量与额外工具工作增加了多少，这些代价是否值得？

以上是研发记录要回答的问题，不注入产品作为固定评分清单。评分标准按任务自然形成，主观部分优先用户盲评，客观部分利用已有运行、材料或可核对事实；顾问自己的评分不是独立真值。

选择少量跨类型任务，并保留未参与调试的任务。重要结果重复运行，避免一次幸运输出当成稳定优势。看到案例退化先分析机制与材料问题，不直接把该案例的规则加进通用提示词。

资源减少而效果未提升，只能记为效率改善；资源增加而效果没有相称收益，不默认保留。两种语言分别记录表现，不用抹平语言差距代替提高各自上限。

## 7. 实施时的取舍与停止条件

- 优先完成 P1、P2、P3，再补 P4；P5 的最小回归随相关改动进行。
- 复用现有入口，一次已有顾问调用内完成分析与贡献。不额外调用模型生成“评价标准”。
- 不为模块整洁或报告完整度进行无关重构，不增加新的强制阶段门、功能开关或工具。
- 材料量按信息价值组织；若预算调整导致关键证据丢失，先修选材，不把更少字符当收益证明。
- 没有实质发现、不改善产物、只是重复已有意见时停止相应工作；已确认的失败依然保持失败，不能用 keep 掩盖。
- 如果效果只在个别任务出现，保持实验结论范围并继续检查泛化，不写成“全领域超越强模型”。
