# 英文模式多轮中文辅助泄漏修复

开发修订：**english-multiturn-1**。本地修复、离线回归与一次真实故障包重放完成；运行实例仍需重启加载。本文件记录的是语言边界修复，不是模型能力或产品运行效果基准。

## 真实复现与根因

实际多轮会话中，原始输入“继续工作”已经被译成“Continue working”，但注入包的标题是英文，Current intent 与六项新增指导却是中文。保留的故障包长2591字符，属于英文输出规则失效。

当 englishTask 缺失或字面量/语言校验失败时，旧生产分支捕获异常后直接返回原始优化响应；后续只补译用户任务，并因“已有辅助”保留了未校验的中文辅助。多轮里的中文历史会提高模型回中文的机会，触发了这条错误回退。原日志还在发生校验异常前抓取诊断，因此 englishExtractionFailure 曾显示null，增加了定位难度。

## 修复行为

- 任务译文与辅助字段独立校验；当前轮译文不合格不再跳过辅助校验。
- 有中文辅助或无有效任务译文时，把需要翻译的已知字段合并为一次保真翻译，不逐条另起调用。正常英文输出不增加调用。
- 只翻译意图、建议、问题及咨询说明等已知正文槽位，不改原始引文、关系枚举或来源/权限字段。每项独立保护代码、路径、数值和明确字面量；翻译后的字段编号及占位符必须完整匹配，再整体校验。
- 批量修复失败只保留已经校验的英文辅助。任务译文仍可沿用独立保真回退；无法解析的响应不再作为英文辅助回传。两种失败不再混为“原始输出可以直接用”。
- v3解析入口与结构化旧包再次渲染也加了纯校验兜底；原中文模式保持原行为。
- 英文提示词明确覆盖续接轮次；JSON重试提示使用英文。修复字段、耗时和用量进入实际请求/诊断记录。

没有强制最终答复使用英文。用户要求中文回复、原话逐字引用、代码/路径/精确标签中的中文仍可能合法保留。

## 验证

20份定向离线测试文件，node --test汇总 **179通过、0失败**，其中新增12项多轮回归。覆盖初始任务→中文续接→确认的实际adapter流程、缺失englishTask、纯英文零额外调用、修复失败保留有效英文、未知字段/占位符拒绝、代码/路径/标签、持久缓存与取消/迟到隔离。

实际故障会话的结构化中文辅助从插件状态中捕获，没有浏览项目文件。仅用 **deepseek-official/deepseek-flash** 做了一次批量修复：

- 耗时约10.3秒，报告用量4137 token。
- englishTask、intent.text和六项add共8个字段一次完成。
- 六项指导全部保留，正文通过英文校验。
- 关键代码符号 requestAnimationFrame(frame) 出现次数保持3次。

## 生效与试用

重启DSH并刷新原网页，确认 prompt.effective.revision 为 **english-multiturn-1**；实际优化后核对 lastRequest.promptRevision 同一标记。英文开关打开后，在同一任务中依次发送初始请求、“继续工作”、具体纠正，检查实际辅助正文保持英文；路径、代码及明确中文标签应保持原值。

不能用界面是中文或用户要求中文答复，判断优化注入失效；本次检查对象是新增辅助正文。若批量翻译不可用，部分辅助可能被省略，但不会把原始中文当合格英文注入。
