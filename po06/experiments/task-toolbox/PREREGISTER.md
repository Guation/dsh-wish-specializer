# Three.js 临时工具箱：开发试点预登记

范围：验证工作模型（本会话）真实创建和调用任务工具、读取图像/测量、修正车辆并复用同一入口。不是自然模型胜率或成品审美对照；不据此宣称 token 节约或 Three.js 达到 Blender 水平。

原始试点目标：在隔离目录生成一个可旋转预览的 Three.js 概念车辆 HTML，保留车身、轮组、座舱、尾翼的稳定部件身份，完成后续装配与外观调整，并可脱离制作服务独立打开。此试点不改变任何用户正在测试的作品。

开发构造：起始参数故意包含两个可观察的装配/比例问题。具体值由工具初始配置记录，不能在修正后重写初始证据。工作模型必须先读取实际截图和 inspect 结果再修改；这是受控工程实验，不伪装成盲测。

工具需求：用同一入口进行部件查询、参数修改、固定机位截图、版本对照和独立 HTML 导出。优先使用本机现成 Three.js 及 Edge，不下载依赖、不启动替代 DSH GUI。截图在隔离浏览器中执行；每次结束清理自己启动的浏览器。

预先约定的观察：

- 网格在真实浏览器中渲染，无运行异常；图像真实交给工作模型读取。
- 测量绑定部件和场景版本，能指出起始可疑关系；包围盒检查只证明几何范围，不当作精确碰撞或审美评分。
- 第一次修正后复查；另一处问题再次使用同一工具接口完成修正，没有重写工具来伪造复用。
- 保留初始、修正一、修正二的场景版本、截图和结果，允许比较与回退。
- 最终 HTML 无制作服务器依赖，禁用 HTTP(S) 网络仍可打开。
- 工具结果使用 taskToolbox 版本 1 的事实信封记录入口、操作、场景版本、可见对象和证据路径。信封是工具自报元数据，宿主将来绑定真实调用，不赋予自动验收通过。

本轮总 token 无独立可核对计量，明确缺失；记录每个工具调用的运行时间与输出。后续 P4 要另行做自然任务/有限对照，不能把本受控试点当作对照胜利。
